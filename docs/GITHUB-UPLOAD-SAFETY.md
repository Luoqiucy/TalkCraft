# GitHub 上传范围与隐私检查

日期：2026-10-31。范围：为当前项目准备上传排除规则。本轮未创建远程仓库、未推送文件，也未修改供应商配置、用户历史、录音或数据库。

## 默认保留在本机

- `.env`、其他环境配置、私钥、证书和常见凭据文件。
- `.local/`（含本机配置、参考项目和审计结果）、`.tools/`、`node_modules/`。
- Rust `target/`、Vite `dist/` 和 `public/react/`、生成的 Tauri schema、EXE/DLL/安装包与压缩包。
- 历史、录音、备份、导出目录及 SQLite 数据库和配套日志。
- 用户设置文件、运行日志与 `reports/` 的真实调试归档；仅本目录说明 `reports/README.md` 纳入源码。
- 音频文件默认排除；仅明确保留当前四个程序提示音文件。运行时 JSONL 默认排除，仅保留两份已存在的人工 ASR 测试语料。
- `design/stitch-prd/` 和 `悬浮栏_prd/` 参考原型及截图。原型HTML中存在密钥样式表单内容，未更改原件，也未将其当作正式运行配置；这些参考归档默认不上传。

上述排除只影响普通 Git 收录行为，不删除或移动文件。项目源码、锁文件、图标、主要开发文档和测试继续保留。

## 本轮核对方式

1. 检查项目根目录与配置/历史存储路径；用户数据主要位于应用用户数据目录，独立于代码目录。
2. 使用临时 Git 仓库并指定当前工作目录，按真实 `.gitignore` 生成候选清单；未初始化或更改项目根目录的 Git 仓库。
3. 用路径样例验证密钥配置、录音、数据库、日志、构建文件被排除，同时源码、锁文件、ASR语料及必需提示音仍可纳入。
4. 在候选文本中检查常见 GitHub/API/AWS 凭据格式、私钥头、凭据字面量和带账号密码的URL。输出只包含路径、行号和类型，不包含命中值。
5. 初次扫描的原型命中已通过排除参考归档解决；其余命中核对为测试凭据、占位文本或拒绝危险URL的测试用例。文件名和模式扫描不能保证检测任意格式的秘密，因此首次提交前仍需审阅实际暂存清单。
6. 二进制资产未进行OCR；候选图片主要是程序图标与设计图标，参考页面截图已经排除。详细审计清单保留在被忽略的 `.local/github-preflight/`，不上传。

核对结果：40个路径保留/排除检查全部符合预期；候选文件391个（约11.4MB），其中332个文本文件经过模式扫描，未留下尚未核对的高置信凭据命中。查询参数扩展检查的7处命中已核对为JavaScript等值比较或脱敏测试用例。此结果对应当前文件，不代表以后新增文件会自动完成内容审查。

普通测试没有发现读取被排除报告的依赖；旧手动联网验证脚本 `scripts/verify-synthetic-chain.mjs` 使用本机 `reports` 中的合成音频，换机后需重新准备该音频，不能把缺少归档写成验证通过。

## 后续提交规则

- 首次先提交本机，再发布 GitHub 私有仓库；首次暂存后重新核对清单及敏感内容。
- 使用常规 `git add`，不要对忽略文件使用 `git add -f`。
- `.gitignore` 不会撤回已跟踪或已上传的文件；若日后发现凭据进入提交，需停推、撤销对应凭据并处理历史，单纯新增忽略规则无效。
- 真实账号密码、API Key、录音、个人记忆与生产数据库不进入私有源码仓库。
- 新电脑安装依赖并重新构建前端/桌面；本机配置需重新填写或通过适当的安全机制迁移。
