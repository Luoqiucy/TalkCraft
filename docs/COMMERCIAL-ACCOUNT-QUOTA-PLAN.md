# TalkCraft 账号、用量与订阅改造方案（拟议）

日期：2026-09-28。状态：Phase 2 商业化开发路线；账号、付费及服务端额度尚未实现。用户已决定结束 Phase 1，并将 Phase 2 从原 ESP32-S3/Wi-Fi 改为软件商业化；硬件开发延后，后续编号未定。未提供证据的量化及 macOS 测试仍保留未验状态。

## 现状与目标

当前 React/Tauri 主程序及 Electron 预览壳调用本机 Node 服务；本机服务使用用户配置的火山 ASR、文字模型及 Firecrawl 等服务凭据。历史在应用用户数据目录，且可关闭保存、过期或删除。Phase 2 首个切片新增与历史独立的**本机非计费用量统计**；尚无账号、云端网关、会员、支付或可信用量账本。因此不能把隐藏本机 API 输入框、读取历史条数或本机统计当成付费版本。

商业版目标是：用户注册/登录后直接使用听写、提示词预设、翻译与问答；桌面端只持有自身登录会话，不持有 TalkCraft 的供应商主密钥；后台控制服务调用、功能权益和免费/付费额度；用户在首页侧边可查看**真实使用统计**和**服务端确认的额度余额**。

## 推荐边界

```text
React 工作台 / HUD（Tauri；Electron 仍为预览）
  → 本机录音与任务状态、账号会话
  → TalkCraft HTTPS 服务端：鉴权、限流、权益、任务、用量账本
  → ASR / DeepSeek、OpenAI、方舟 / Firecrawl / 天气等供应商

本机历史、录音保存和个人词典：仍按现有用户隐私设置管理
支付平台 → 已验签异步通知 → 订阅状态 → 功能权益
```

- Node.js 服务可复用现有 Agent、工具和供应商适配逻辑，但需拆分“本机桌面能力”和“云端受控调用”。现有 `server.mjs` 不应直接暴露为公网商业 API。
- 供应商密钥只存服务端密钥管理系统，客户端不可取得。桌面会话使用系统浏览器登录、授权码与 PKCE，短期令牌放系统安全凭据存储；不放进 React 状态持久化、localStorage、历史或诊断包。
- 云端执行 ASR、文字模型和搜索时，界面应清楚说明音频/转录/提问会发送给 TalkCraft 服务及实际供应商；本机历史、录音副本和知识库不能因账号登录自动上传。
- 用户不再需要配置供应商 API。现有自备密钥模式仅作为开发/高级本地模式保留，并与商业额度、供应商承担成本明确分开；退出该模式后不能静默回退到用户旧密钥。

## 首页侧边统计

参考截图的**信息层级**，沿用 TalkCraft 自己的视觉体系、术语和图标，不照搬品牌、排版或示例数字。侧栏建议一张“本期使用”卡、一张“账号方案”卡；小窗口时折叠或移至首页顶部。

| 指标 | 计算口径 | 来源与展示规则 |
| --- | --- | --- |
| 转写字数 | 成功 ASR 原始转录的可见字符数，排除空白；一次录音只计一次 | 服务端任务账本；本机开发模式只能标为“本机统计” |
| 问答文字 | 用户成功提交的问答文字字符数；与 AI 输出字数分别统计 | 服务端任务账本；不得与转写字数相加后冒称同一指标 |
| 口述时长 | 成功接收音频的有效时长 | 服务端确认的秒数；取消/空音频单列，不冒称已完成 |
| 平均口述速度 | 已完成转写字符数 / 对应有效录音分钟数 | 样本不足时显示“暂无数据” |
| 免费/会员额度 | `used / limit`，并显示明确周期及下次重置时间 | **只**显示服务端 `/me/usage` 返回值；未登录/离线显示“暂不可核对”，不本地推算余额 |
| 节省时间 | 如要上线，必须先确定人工打字基准及公式 | 首版不展示，避免未经验证的夸大值 |
| 个性化比例 | 目前缺少可计量的个性化流程 | 首版不展示 |

“转写字数”与“会员计费单位”可以不同。建议套餐首先使用可解释的**月度转写分钟数**和**月度 AI 处理字符/次数**两类额度；供应商成本另按 ASR 秒数、模型输入/输出 token、搜索/抓取次数内部核算。具体赠送额度、价格、计费周期和免费功能清单在成本实测后定，不复制参考截图的 `2,000 字`。界面必须写明超额后的行为（停止云端调用、提示升级或购买加量包），不能在请求完成后意外扣费。

## 服务端最小数据模型与接口

开发进展：独立网关和 SQLite 事务账本见 `docs/COMMERCIAL-GATEWAY.md`。本机开发版已支持最小邮箱/密码账号、会话及受控 ASR/文字请求；这不代表邮件验证、公网部署、桌面登录、订阅权益或真实商用计费已完成。旧 JSON 账本保留作单进程基线，正式计量路径将以 SQLite 事务实现为基础，不把本机统计导入账单。

- `accounts`：账号 ID、认证主体、状态；原始语音/转录正文不进入账号表。
- `plans`、`entitlements`：套餐版本、功能开关、额度和生效/失效时间；变更保留历史版本。
- `subscriptions`、`payment_events`：支付平台对象 ID、已验签事件 ID、状态；回调按事件 ID 幂等。
- `usage_events`：不可变事件 ID、账号 ID、任务 ID、模式、计量类型、数量、发生时间、状态、供应商用量与成本元数据；默认不存原文或原音频。
- `usage_periods`：每账号每计费周期的聚合视图；历史删除或保留期缩短不改写已产生的账务事件。
- `tasks`：任务 ID、幂等键、预留额度、完成/取消/失败状态，重试关联同一任务。

接口建议：`GET /me`、`GET /me/usage`、`GET /me/entitlements`、`POST /tasks`、流式任务端点、`POST /tasks/{id}/cancel`、支付平台回调。每次任务先由服务端检查会话、套餐、额度与并发上限，再预留预算；结束时按真实结果结算或退回未使用额度。重复提交、网络断线、迟到结果和客户端重放不能重复扣减。支付完成页面只显示“待确认”，以服务端验签和实际权益状态为准。

## 分批落地与验收门槛

### 2026-09-29 额度账本核心开发状态

`src/commercial/usage-ledger.mjs` 已实现**单 Node 进程开发用**持久化账本，必须由未来已鉴权的服务端提供 `accountId`、周期、套餐限额和经服务端核实的实际数量。每个账号的任务 ID 与计量类型组成幂等键：预留占用余额，成功按实际量结算并释放差额，取消/失败释放全部，取消后的迟到结果拒绝结算。支持 `asr_seconds`、`ai_characters`、`search_calls` 整数单位，具体免费/会员额度未定。账本事件仅保存标识、数量、状态和时间，不存录音、转录正文或供应商密钥；测试路径显式注入，未写入用户历史目录。

当前文件持久化仅保证**同一进程内**请求串行和重启恢复，不保证多服务实例、跨机器或崩溃边界的商业级事务安全。正式上线需数据库事务、唯一约束、故障恢复/对账和备份；服务端账号鉴权、权限判定、真实供应商调用及用量核验也尚未接入。桌面端不能直接传入可信账号 ID 或结算数量。本机 `GET /api/local-usage` 继续标为非计费统计；`/me/usage` 尚未开放，UI 不展示正式余额。订阅套餐价格、重置日和支付渠道仍待确定。

1. **统计基线**：定义字符口径及四模式事件，增加与历史保存设置无关的本机最小用量计数；侧栏只显示可证明的“本机统计”，无模拟会员或配额。覆盖成功、失败、取消、重试、历史删除、重启和跨窗口同一任务去重。
2. **账号和服务网关**：注册/登录/退出、会话安全存储、服务端供应商密钥、账号隔离、ASR 与 Agent 受控代理；真实用户不再填 API。验证真实 ASR/模型/搜索、撤销会话、断网与服务不可用。
3. **额度与会员权益**：不可变用量事件、预留/结算/退款、并发与幂等、功能门控、`/me/usage`；侧栏正式显示本期进度及重置时间。用两个设备同时调用、重试、取消、跨周期、支付状态变化做并发测试。
4. **支付接入**：先选目标市场和商户主体，再接相应支付渠道与订阅生命周期；验证支付成功、失败、退款、取消、过期、重复/乱序回调和对账。不要先根据客户端跳转成功放开会员功能。
5. **商业试运行**：小规模真实用户测 P50/P95 ASR、AI、搜索时延及单位成本、账本误差、客服/退款流程。价格和免费额度用真实成本与留存数据确定。

本方案已作为 Phase 2 路线启动。Electron 迁移、延期的硬件开发和商业后端分别记录进度；本机统计不能用于扣费或防篡改额度。Windows 开发版唯一入口与构建规则仍按 `AGENTS.md` 执行，安装包仍留到 Phase 4。
