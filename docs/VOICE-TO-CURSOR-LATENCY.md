# 语音到光标：可见等待与安全输出

2026-09-29 的增量实现保留现有 React/Tauri/Node 架构和四种模式。

| 模式 | 可见过程 | 外部光标输出 |
| --- | --- | --- |
| 听写 | 音频准备 → ASR → 原始转录 | 完整 ASR 原文一次性输出；不调用 AI、不润色 |
| 提示词预设、翻译（本机服务使用 DeepSeek） | 模型返回的真实片段逐段显示在 TalkCraft 结果区，悬浮条显示末尾短预览 | 完整结果通过一次原生调用输出；途中取消不向外部应用写入片段 |
| 问答 | 沿用既有搜索/模型进度和可用的回答预览 | 完整回答确认后一次性输出 |
| 其他文字提供器、账号模式 | 沿用原有一次性结果 | 完整结果一次性输出 |

流式预览请求没有搜索工具；只用于提示词预设和翻译，不把听写转成编辑任务。模型流失败或用户取消时清除未完成的预览，保留录音/原始转录，且不自动重复调用模型。外部应用的通用文本框无法保证“逐字插入后可靠回滚”，因此本期**不向外部窗口流式写半成品**。这换取可验证的取消安全，代价是光标位置仍要等完整结果；用户先在工作台看到片段。若未来做真正的外部流式落字，需要限定目标控件、事务性回滚和跨应用实测，不能只在失败后盲发退格键。

历史开启时，每次成功 ASR 尝试可保存 `stopToFinalMs`、`audioPreparationMs` 和 `asrRequestMs`；未开启历史时不为测量偷偷保存正文或音频。三者分别对应停录到可用、录音文件解码/重采样、请求到最终转写，数字不能混用。历史与音频写入仍按任务顺序进行，但不再阻挡转写启动。火山 ASR 仍按 100ms 间隔发送 200ms 音频片段，长录音可能有明显重放等待。真实 P50/P95、首次可见片段、外部落字总时间须用同一录音、真实目标应用和真实服务另测。

热词配置参见 [ASR-PROVIDER.md](ASR-PROVIDER.md)。本轮协议与 HTTP 取消测试均为本地替身；不能把它们当成真实豆包热词收益、云端首字速度或 Windows 外部应用回滚验收。
