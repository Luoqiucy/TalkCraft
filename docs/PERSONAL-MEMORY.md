# TalkCraft 个人长期记忆（开发版）

更新：2026-09-30。本文描述当前代码，不代表公网商业服务已上线。

## 数据边界

- 会话上下文只用于当前问答；联网证据有时效并保留来源；个人词典仍是独立设置；长期记忆只保存用户明确确认、可查看与删除的稳定偏好、事实、项目和专有词。
- 当前不从聊天全文自动抽取人格或偏好。问答输入以“记住……”开头时，桌面端直接保存到本机，不调用模型或公开搜索；其他信息需在“个人记忆”页手动确认并填写“为什么记住”。
- 每条记忆有独立ID、owner、类型、内容、解释、来源记录ID、是否独立保留、用户确认状态、版本、创建/更新时间、复核时间、暂停/删除状态、云端选择和同步状态。检索最多取5条、合计内容限制1600字符，只用于问答；普通听写、提示词预设、翻译不接入记忆。
- 记忆数据库位于历史用户数据目录的 `personal-memory.sqlite`，使用 SQLite 事务与 WAL，不在项目目录、EXE目录或浏览器存储中保存正文。访客使用本机稳定的独立profile；已登录账号的owner来自服务端验证的桌面桥接身份，不接受浏览器传来的ownerId。账号变化/过期时拒绝读取，不将游客数据自动并入账号。
- 问答实际使用的 memoryId、字符数和检索耗时进入执行记录，不写入记忆全文。字符数是提示词增量的近似值，不是实际模型token量。个人内容不会作为独立搜索词发送；云端模型回答时，命中的短记忆会作为模型上下文发送，因此“本地保存”不等于“本地推理”。
- 用户删除历史记录或清空历史时，关联且未声明独立保留的记忆同步标记删除；独立记忆不受影响。记忆单条删除和清空会生成同步删除操作（仅已选且同步开启时）。

## 用户操作

React工作台新增“个人记忆”：手动新增并说明原因、查看、编辑（乐观版本冲突检测）、暂停单条记忆、删除、清空全部、导出JSON、暂停学习建议、关闭回答使用、选择账号同步。自动学习尚未实现；当前只接受明确保存，不根据重复行为自动生成事实。

## 开发版同步协议

本地默认关闭云同步；只有登录账号、用户开启同步并逐条选择的记忆才进入outbox。桌面桥接从服务端会话读取账号身份并代理同步，不把Bearer令牌交给React。服务端从Bearer会话解析账号，忽略客户端ownerId；同步操作按操作ID幂等，使用baseVersion检测冲突，SQLite事务内更新数据、操作账本、变更序号；删除记录保留墓碑，阻止离线旧副本复活。拉取使用账号独立cursor。未配置服务端验证权益时，网关拒绝云同步；没有假购买或假成功。

跨设备目前只通过本机隔离客户端与本机SQLite网关的集成测试；公网部署、真正两台设备、支付会员权益和备份/删除政策均未验收。Node `node:sqlite` 是开发运行条件，正式服务前必须固定与评估支持版本。

## 清理与限制

删除记忆不清除用户自行导出的副本。删除已同步记录会提交墓碑；账号注销、服务端备份清理、到期账户数据保留期尚无正式策略。关闭历史保存不会阻断用户明确另存记忆；创建独立记忆必须在界面明确解释。

目前长期记忆匹配是小范围关键词重合，不是语义向量检索；不会扫描全部历史。自动偏好建议、云端加密策略、跨设备冲突解决UI和真正公网服务仍待后续实施。

2026-09-30补充：问答上下文采用共享结构化请求；当前会话事实带来源轮次与原文片段，与长期记忆分离。明确“记住……并查……”会先显式保存记忆，再执行后续查询；普通自述只显示可确认的记忆建议，不自动写库。桌面和账号检索现共用同一份受限水果类别/关系评分代码，可区分“喜欢吃香蕉”与“偶尔吃苹果”，并按类别回答“我平时吃哪些水果”。这只是针对当前已支持的常见水果语义，不是通用向量语义检索；其它类别仍以精确词项为主。无相关私有事实时不把偏好问题交给公开搜索。详见 `reports/2026-09-30-context-routing-memory.md`。
