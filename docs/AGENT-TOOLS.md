## 改动前缺口

1. 搜索和天气由条件分支直接调用，没有统一的工具定义、参数验证、执行结果与阶段事件。
2. DeepSeek返回标题或短摘要时只能补充搜索，不能读取具体页面。
3. 前端等待 `/api/search` 完成后才能看到结果，无法区分实际的搜索、网页读取和整理阶段。
4. 没有网页读取的SSRF边界、重定向校验、正文大小/类型限制和抓取时间记录。
5. 搜索轮次受限，但搜索、网页读取、天气之间没有统一的总工具调用预算。

## 当前轻量流程

`语音转写 → 当前模式 → 问答意图 → 工具注册表 → 有界工具循环 → 证据质量检查 → 模型回答`

- 听写、提示词、翻译保持原处理路径，不注册或调用联网工具。
- `search_web`：复用当前提供器的真实DeepSeek原生搜索；记录查询、来源、响应模型和用量。
- `read_webpage`：服务端读取公开HTTP/HTTPS网页；每次重定向重新校验；DNS实际连接使用受控lookup并阻止本机、内网、链路本地、保留和文档地址；不接受凭据URL；只接收HTML/XHTML/纯文本；单页512 KiB、正文24000字符、默认10秒、最多3次重定向。
- `get_weather`：复用Open-Meteo结构化真实天气，不需要新增凭据；天气观测和预报继续分开。
- 每次请求生成独立UUID任务ID；默认最多6次工具调用、最多2次补查、总期限45秒。同一失败网页和相同查询不循环重试。
- 工具结果包含来源URL、正文摘要、发布日期、抓取时间、读取状态、耗时和安全错误；网页文字按不可信外部资料处理。
- HTTP以NDJSON实时发送 `searching`、`reading`、`weather`、`answering` 阶段。取消连接会中止当前任务，信号检查阻止后续工具与迟到结果交付。

## 证据与回答规则

- 产品问题先保留原名称，再定位官方英文名、官网、投资者关系公告或官方配置页；存在官方链接但没有正文时不算取得完整官方资料。
- 指定年款必须在资料中得到确认；记录证据年份和冲突标记，不混用其他年款。
- 标题、URL或过短摘要不足时才读网页；已有足够正文时不重复读取。
- 搜索/读取失败不证明对象不存在，也不能静默用旧知识伪装实时结果。
- 模型只获得工具实际返回的资料和真实来源目录；页面中的指令不会改变系统规则或触发其他工具。

## 当前限制

- 网页读取器只提取静态HTML/纯文本，不执行JavaScript，不支持登录、Cookie、PDF和付费墙。
- 某些站点可能拒绝服务端访问或只返回客户端壳；此时显示读取失败并保留已有搜索证据。
- 当前是确定性轻量编排器，由本地意图和证据质量选择工具；没有引入大型Agent框架，也没有允许模型调用任意工具。

## LangChain / LangGraph 增量迁移（2026-09-20）

- 固定运行依赖：`langchain@1.5.11`、`@langchain/core@1.2.11`、`@langchain/langgraph@1.4.16`、`zod@4.6.5`；均为 MIT，当前 Node 24.14.1 满足要求。
- `src/agent/langchain-tools.mjs` 把现有真实工具注册表封装为 LangChain StructuredTool；参数仍由 Zod 和后端执行器校验，权限、SSRF防护、`callId`/事件和6次预算不交给提示词。
- `src/agent/langchain-model.mjs` 用 Runnable 包装现有 OpenAI/DeepSeek/方舟/Ollama 提供器，保留既有请求协议、元数据和取消。DeepSeek 原生搜索仍用已验证的 Anthropic 兼容自定义适配，不假设聊天适配器能表达搜索。
- `src/agent/langgraph-weather.mjs` 当前图节点为 `understand → execute_weather → check_evidence → generate_answer`。`/api/agent` 是天气问答的单请求端到端路径；工作台只在服务报告 `agentEngine=langgraph`且判断为天气时调用它。
- 通用搜索、产品参数和指定网址仍走旧轻量编排。四个模式中只有问答可进入 Agent，听写、提示词和翻译不加载框架也不联网。
- 框架采用延迟加载：服务启动导入路由约1.4秒/106 MiB RSS增量降至约14 ms/1.76 MiB（独立 Node 单次测量，不是桌面整机基准），首次真正进入 LangGraph 时才付出加载成本。
- 回退：删除或将 `.local/asr-test.env` 中 `TALKCRAFT_AGENT_ENGINE` 设为 `legacy`，重启后只使用旧流程。代码未配置时的默认值是 `legacy`；2026-09-20桌面更新后本机显式配置为 `langgraph`。一个请求只走选中的一条路径，不会同时向新旧两路模型付费。

## 执行过程与参考来源界面（第148轮）

- 每个工具调用拥有独立 `callId`，所有事件同时携带任务 `taskId` 和单调递增的 `sequence`。界面按事件ID去重、按序号排序，不推测或展示模型内部思维。
- 工作台使用原生 `details/summary` 折叠结构。处理中显示当前真实阶段和已用时间；完成后默认保持浏览器当前展开状态，不在更新时强制收起。
- 工具事件保存开始、完成、失败、取消、超时、调用上限、耗时、搜索词、搜索返回数量及实际读取URL。最终回答完成来自实际模型HTTP响应，不由计时器伪造。
- 来源URL经过凭据和敏感查询参数清理，再生成稳定 `sourceId`。来源区分仅命中、取得摘要、读取正文和读取失败；发布时间与抓取时间分别展示。
- 回答中实际出现的 `[n]` 引用映射到同一顺序来源的 `sourceId`，可定位到来源卡片。未被回答引用的搜索结果仍可在执行详情中查看，但不会标为“回答已引用”。
- 结构化天气单独显示提供方、地点、观测/预报时间及关键字段，不伪装成网页正文。
- 历史仅保存必要事件、最多600字符的来源片段和清理后的链接，不保存完整网页正文、模型请求、Cookie或凭据。旧记录没有轨迹时明确显示未保存，查看历史不发起网络请求。
- 历史详情提供独立“重新查询”按钮，仅对保留了问题文字的问答记录启用。用户确认后才按当前联网工具和模型配置发起新请求，并把新过程保存为同一记录的一次新尝试；单纯查看历史始终不会联网。

## 通用产品问答质量修复（2026-09-30）

- 产品问题解析保留原问句，并分离品牌、品类、显式型号、最新意图、地区/年份和所需字段；先按原问题搜索。数字与 `Ultra/Pro/Max` 等后缀分开比对，避免 i9/L9、15/15 Ultra/30 Ultra 混淆。
- 搜索结果必须同时匹配对象、类别、时间范围和所需字段；摘要长度不再单独代表充分。资料不足时记录字段缺口，搜索循环最多补查2次、所有外部工具总计6次、45秒截止，取消继续生效。
- “最新”须有官方产品线/发布日期措辞支持。最终模型回答会再次经过后端检查；未确认最新款时，改为说明证据缺口并展示实际相关链接，不把候选型号写成结论。当前测试覆盖语序在品类前后的“手机最新款”问法。
- 只有两个不同来源共同确认相同数字型号、品类和近似品牌名时才提出规范名称候选；仍保留用户原始转录，不写入词典。来源ID随候选一起记录。
- 网页读取支持 gzip、deflate、br，分别限制压缩/解压与正文长度；覆盖整体读取时限、动态空壳和重定向安全校验。传给模型的工具JSON先按字段缩减再序列化，避免截成无效JSON。
- 在实际构造模型消息时记录来源ID、片段数、字符数、截断标记及证据判断；未采集字段保存为“未记录”。不保存API凭据、完整模型请求或网页全文。旧历史里已保存的 `0` 不作猜测性回填。
- 尚未实现逐项语义蕴含检查，也不能保证所有厂商动态页面可读取；真实复测中，一加规格页返回动态壳，小米汽车来源有不同车型/配置命中。结果见 `reports/2026-09-30-agent-product-quality.md`。

## 口语理解与实际工具循环回归（2026-09-30）

- 生产入口是 `/api/agent → resolveQuestionContext → answerDaisyQuestion → createAgentToolRegistry`。结构化请求由服务端构建，一份请求对象同时约束规划查询词、后端证据检查和最终回答；前端天气守卫不参与完整对象解析。
- 请求对象最少保存原始转录、解析问题、候选对象及确认状态、品类、显式型号、字段、时效、地区、会话证据与歧义，并标记每个值来自用户原话、会话中用户确认，或未知候选。不得从前轮AI回答“确认”型号。
- 型号识别必须保留区分后缀，并验证完整型号边界；品牌或类别的显式冲突不能因数字相同而放行。数字容量不能仅凭四位数自动成为年款。
- 证据缺口将被作为真实摘要交还 Daisy：对象是否确认、用户字段中哪些已得/缺失、日期或地区是否冲突、下一步更适合官方公告还是规格正文。决策不根据正文长度单独放行。
- 搜索摘要缺字段时，`read_webpage` 可读取相关对象的正文；无摘要结果可先读取以确认对象。每个URL每任务最多读取一次，读取和补搜同享45秒与最多6次调用。每轮的模型提议、重复/无效拒绝与外部实际执行分别计数；重复拒绝不会无限延长规划轮次。
- 查询“最新发布、已发售、当前在售、旗舰”是不同目标。官方发布日期、开售日和产品线可支持相应结论；网页自称“最新”或大数字型号本身不构成证据。用户对象有歧义时先确认，不用相似型号参数代答。
- 本轮固定回归覆盖语序、口语连接词、噪声型号、类别与品牌冲突、价格/续航字段、短摘要读页、标题先读页、无关长摘要补查、部分证据与张家港天气追问。全量自动测试456/456通过；没有真实云端联网复测，因此不报告真实准确率或延迟提升。
- 引用逐条语义支持核验仍属于后续批次；当前只校验对象匹配、字段/时间证据和引用来源映射，不能声称完成所有数字的语义溯源。

## Daisy 搜索计划、补查与 Firecrawl（2026-09-30）

- 生产工具循环仍由 `answerDaisyQuestion` 负责；模型提出查询/工具，服务端校验和执行。模型的简洁查询不被原始整句强制覆盖；显式型号和用户给出的关键字段、地区及时效仍由程序保留校验。
- 后端注册 `scrape_webpage`：Firecrawl v2 scrape，接收正文 Markdown、标题、来源URL、发布时间（如果提供）、抓取时间、耗时和服务返回的用量字段。Key 不下发 UI。`read_webpage` 是本地静态读取，`scrape_webpage` 是 Firecrawl 读取；不会在每个 URL 上自动两次读取。需要第二种方式时由后续工具计划显式请求并消耗另一次调用预算。
- Firecrawl 地址、输入URL与返回最终URL均过现有公共地址/DNS校验；有超时、取消和响应/抽取文本上限。网页文字视作外部资料，不执行网页指令。Firecrawl credits 只记录服务实际返回的数值，没有返回费用时不推算成本。
- 初次答案后只有新增工具证据才推动有限核对；工具重复提议拒绝与实际外部请求分别记录。总预算仍是6次工具调用、45秒，取消后无新调用。
- 后续问句可携带最多6条不超过360字符的历史工具来源摘要以及稳定sourceId、脱敏URL和日期；仅在指代追问中使用，不重新联网、不把AI旧答案当证据，历史详情仍不自动触发网络。
- 同 URL 单次比较详见本轮报告；自动测试464/464通过，Firecrawl真实抓取只测一条 URL，真实模型完整问答待测。
# Agent 请求上下文与个人记忆（2026-09-30）

问答生产入口均应调用共享请求理解入口，再进入 Daisy 工具循环；网关不得绕过当前对象/字段解析。短期上下文（当前话题、地点、日期、来源线索）与长期记忆、词典和有时效的外部证据分开。长期记忆只在回答阶段按问题检索少量经用户确认的条目，记录命中的memoryId；不得将其自动拼进公开search_web/read_webpage查询。用户可在工作台的个人记忆页管理，或以明确的“记住……”命令直存本机。同步是独立授权能力，默认关闭且服务端权益未验证时拒绝。字段、权限及同步接口见 `docs/PERSONAL-MEMORY.md`。

## 结构化请求与多轮路由（2026-09-30）

- 搜索与天气工具接收同一份服务端 `request`：原始输入、解析问题、任务/会话标识、行为类型、对象/型号、所需字段、约束、候选、每字段来源以及有限上下文证据。桌面和账号网关共用 `resolveQuestionContext`，客户端不能自行覆盖可信账号身份或证据。
- 更换对象时先丢弃旧对象专属属性；只有明确的续查任务约束（例如“闲鱼近期成交价”）可以继续带入。模型上一轮回答不属于用户事实，也不是工具证据。
- 天气追问的路由依赖当前活动天气上下文：明确城市替换地点，单独城市名只在天气上下文中作为地点；“明天/后天”保留最近明确地点。任何天气数值都必须来自该轮地点与时间的成功结构化工具结果。
- 个人偏好查询使用私有记忆与本轮用户自述，不注册公开搜索工具；个人信息不进入公开查询词。持久记忆写入由明确用户操作触发且只在后端写入成功后显示成功。
- 连续城市与工具实测、调用次数及限制见 `reports/2026-09-30-context-routing-memory.md`。

## 多轮天气纠正、公司新闻与可选位置（2026-09-30）

- 天气工具使用共享 `resolveQuestionContext` 的有效范围；改口时记录撤销值和新值，只对最后有效范围发请求，并用返回数据日期核验覆盖。未知或不支持的范围不能静默变成今天。
- 缺地点时保留待补任务；城市短答补全地点并继承用户明确的日期。没有明确城市、有效授权位置或工具证据时须澄清/说明缺口。
- 两个城市是两个对象，不拼接成单个地点。当前不支持比较时明确要求选择，不生成混合天气结果。
- 公司新闻按公司对象与文章发布时间窗口评估，分别保留事件时间、发布时间和抓取时间；转载去重，旧闻、无日期和导航页不算作近期新闻证据。
- 位置输入须有用户授权标记及通过服务端校验、未过期的系统位置。明确城市优先；坐标不进入常规日志、历史正文、公开查询词或个人记忆。
- 本轮真实新闻与天气结果、Windows定位待验收项见 `reports/2026-09-30-multiturn-news-weather-location.md`。
