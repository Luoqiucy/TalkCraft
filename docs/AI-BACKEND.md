2026-09-28 Daisy 风格联网问答增量：React 的 `/api/agent` 在配置 DeepSeek 且开启联网问答时进入 `src/agent/daisy-question.mjs`，使用 DeepSeek Chat Completions 流式 Function Calling。模型在受限工具集合中请求搜索、网页读取或天气；后端参数校验、执行、记录 callId/任务事件后，把工具结果作为 `role=tool` 交回同一模型会话。天气位置和日期使用应用已经解析的意图，避免模型参数改坏地名。真实结构化天气证据足够时按片段显示回答；搜索证据不足时不把媒体标题或模型旧知识包装成官方完整参数。最多6次工具、45秒总时限，重复签名不重复请求，取消停止后续步骤。查询对象和会话上下文仍由现有解析器维护。

搜索后端：可在 React“AI 服务与外观”设置中单独填写 Firecrawl Key。配置后优先使用 Firecrawl v2 Search，结果保留真实 URL、标题和摘要；服务失败时回退已有 DeepSeek 原生搜索，诊断记录实际后端。未配置时直接使用 DeepSeek 原生搜索。网页读取仍用本机带 URL/DNS/重定向防护的读取器，未照搬 Daisy 的网页抓取实现。Firecrawl Key 不回显，不进入 Agent 事件或历史。该路径**尚未以真实 Firecrawl 凭据验收**。

本次真实样本：张家港未来七天天气由 DeepSeek `deepseek-v4-flash` 配置（上游返回 `deepseek-flash`）经1次天气工具和2次模型调用得到逐日预报，墙钟3.9秒；理想i9详细参数经2次并行 DeepSeek 原生搜索和2次模型调用约14.5秒，但只得媒体标题、无官方可读正文，按证据门槛报告资料不足。前次旧编排单样本约16.5秒；问题、网络和证据条件并不完全一致，不能据此证明P95或 Daisy 等效效果。Firecrawl 的真实搜索质量/时延、Windows桌面UI、真实语音与长会话仍待验收。

回退：DeepSeek 路径之外仍走现有 LangGraph 天气或旧编排；如 DeepSeek 流式协议在真实服务遇到兼容问题，可在 `server.mjs` 的 `/api/agent` 路由关闭 `useDaisyTools` 分支，原路径与用户历史格式保持可用。不会同时执行两套付费问答。

2026-09-28 增量：React 工作台开启联网问答时，天气和通用问题统一提交一次 `/api/agent`；天气仍走 LangGraph，通用产品/搜索仍走原 `search-orchestrator`，后端在同一 HTTP 任务里顺序执行工具和回答，不双路调用。`firstProgressMs` 与 `totalElapsedMs` 是实际墙钟指标，不能视为云端模型首字延迟。旧 `/api/search`→`/api/process` 保留给原生页面回退。Electron 仅增加桌面预览壳，不改变 Node Agent 所在进程。

## 不变的边界

Tauri/Rust 桌面层、现有前端、火山 ASR、四模式、快捷键、HUD、历史与外部光标输出保持不变。Node.js 服务仍是 AI 边界，不增加 Python 或独立数据库服务。ASR 与文字 AI 的授权和提供器继续分离。

## 已迁移请求

内部配置 `TALKCRAFT_AGENT_ENGINE=langgraph` 开启后，工作台的问答模式且开启联网，被实际意图规则判定为天气问题时，通过 `/api/agent` 一次请求进入：

`understand → execute_weather → check_evidence → generate_answer`

`execute_weather` 调用 LangChain StructuredTool，实际执行仍是已有 Open-Meteo 后端。`generate_answer` 经 LangChain Runnable 调用用户已配置的文字模型。同一图只产生一次模型请求，不再先调新图又调旧 Agent 循环。

当前未迁移：理想 i9/其他产品参数、通用时效搜索、指定网址、无需联网的一般问答。这些仍走原编排器，结果中显式记录 `engine=legacy` 和迁移回退原因。听写、提示词和翻译永远不因本开关进入 Agent。

## 通用搜索证据质量基线

2026-09-22先在旧编排器内完成第一批小范围修复，迁移前保持行为可回归：

- “帮我查、请查一下、查找、搜索、检索、了解一下”等明确查询进入搜索路由；“解释……”“什么是……”以及“检查一下这段话”等反例仍是一般问答。前端联网开关与云端授权仍是必要条件，分类本身不会绕过用户选择。
- 证据充分性同时检查问题对象、所需字段、年份或时效范围及相关可读内容。摘要总长度不再单独决定充分性。
- 读页候选按相关性、缺失字段和来源类型排序。相关摘要即使非空，只要缺少价格、续航、配置、开放时间等问题所需字段，仍可在共享工具预算内读取正文；已读、读取失败及无关来源不重复读取。
- 资料不足时最多沿用现有2次补查、6次工具调用和45秒总期限。诊断保存原始搜索词、补查原因、实际读页及读页原因，不保存密钥或授权头。
- 产品类官方来源必须在该来源自身的标题、摘要或URL中匹配原始型号，通用投资者导航页不能只凭官方域名和正文长度成为车型证据。

通用搜索仍由 `search-orchestrator` 唯一负责预算、补查、终止和取消；本批没有新增LangChain Agent循环。验证稳定后再把相同节点和质量门槛迁入LangGraph，迁移期间不得让新旧编排同时发起付费调用。

## 运行限制

- 工具调用预算默认6，总期限默认45秒；所有工具重试共用同一预算。
- LangGraph `recursionLimit` 默认12，它只是图步数保护，不代替工具调用计数。
- 任务使用原有 taskId/callId/单调序号事件；前端只显示真实工具阶段，不展示模型内部思维链。
- 取消传入图、工具和模型。动态导入本身无法中断，但取消后不会开始工具或交付迟到结果。
- 框架仅在首次进入已迁移 Agent 时延迟加载，普通录音和四模式启动不加载 LangGraph。

## 持久化与 RAG 待办

2026-09-25 React 问答新增可选的本机历史上下文恢复：默认不启用；开启时只从现有 `/api/history?mode=chat` 读取已保存、未过期且完整的问答对，按服务端限制裁剪为最多12条消息、8000字。关闭文字保存时不能恢复，不在 localStorage 另存问答正文。此功能是有限会话上下文，不是个人知识库 RAG，也不是 LangGraph 检查点。天气追问通过共享解析保留原始问题与实际查询词，明确地点优先；一般产品指代仅使用最近一条用户问题补充搜索词，不擅自改写型号。

LangGraph 检查点尚未接入。首版不使用内存检查点冒充重启恢复；后续评估 SQLite checkpointer，与用户历史分库/分类设计，只保存恢复必需状态，恢复由用户显式发起，先以操作ID防重复。

RAG 首版将以本地用户数据目录为边界，不在项目目录保存索引，不扫描整个磁盘。实现顺序：显式导入与去重 → 文字提取 → 带文档ID/版本/页码的分块 → 关键词基线 → 实测中文本地 Embedding 与混合检索 → `search_knowledge` 工具 → 引用验收。在实测模型大小、内存、冷启动和 Windows 兼容之前，不默认下载本地模型；不默认 DeepSeek 聊天 API 具有 Embedding。

## 回退

从 `.local/asr-test.env` 删除 `TALKCRAFT_AGENT_ENGINE`，或设为 `legacy`，重启服务。这不会改动用户历史、录音或模型密钥。代码未配置时默认为 `legacy`；2026-09-20用户退出后已将本机配置显式切换为 `langgraph`并完成统一Windows构建。

## 口语理解与 Daisy 实际调用链修复（2026-09-30）

- `/api/agent` 在调用 `answerDaisyQuestion` 前，先经 `resolveQuestionContext` 创建一份结构化请求，并把原始转录、解析后的查询、对象候选、类别、显式型号、字段、时间范围、地区、上下文证据和歧义一并传入；搜索计划与证据判定使用同一对象，避免前端猜测成为权威对象。
- 产品上下文只从用户明确说过的近期问题继承，不把 AI 先前答案直接当事实。当前请求明确切换品牌/型号时丢弃旧产品对象；“它多少钱”“续航呢”只附加必要对象信息，不拼接完整历史句子。天气“张家港→后天”保持独立回归。
- 高噪声型号（如“18放的这个用型号”）以未确认候选表示。先用有限、保留品牌/类别/字段的查询核实候选；多种对象仍合理时，在列具体价格或参数前由程序要求确认。
- Daisy 工具循环使用证据缺口推动下一次规划。模型过早返回正文但关键字段未核实时，在原45秒/6次实际工具预算内允许有限补查；取消后不启动后续工作。没有任何模型自述会被当作来源证据。
- 普通产品来源的正文读取按对象匹配、缺失字段和摘要长度排序。短摘要即使不是已确认官网，只要对象相关并缺少用户所问字段，就可以继续读取；只有标题的候选先读页核实对象，避免额外搜索先于读取。对无类别名查询补齐价格、续航字段判断。
- React 的 `agentClient` 不再导入 Node 搜索/工具模块。客户端只用轻量天气词守卫处理“关闭联网”提示；完整的意图、上下文与对象解析只在服务端，避免 Vite 把 `node:crypto` 和 Node 工具注册表打进浏览器。
- 真实 DeepSeek/Firecrawl 未在本批次调用。自动替身/路由测试与真实联网效果分开记录。

## Daisy 联网问答工具链路增量修复（2026-09-30）

- Daisy 生产请求保留原问句、解析问题、模型提议的搜索词和实际执行搜索词；程序只补足用户明确给出的品牌/类别/型号后缀/地区/时间/字段，避免用完整口语句覆盖高质量搜索计划。
- 已移除“证据长度/启发式充分”直接令最终生成 `tool_choice=none` 的行为。工具继续可用；新证据出现后才针对缺口要求模型核对，重复提议会被去重且不会无限延长轮次。预算仍为45秒与6次实际调用。
- Firecrawl 通过 `scrape_webpage` 进行可选正文读取，使用现有服务端 Firecrawl Key；本地 `read_webpage` 与 Firecrawl 抓取是独立、可追踪且分别计数的调用，不默认双抓同一个 URL。Firecrawl 原始正文仅作为本次任务工具结果，不写入历史全文。
- 对产品/天气指代追问，客户端可发送少量已保存短来源证据；服务端清理并限长，证据来源标记为之前工具结果，不把前一条 AI 答案升级为事实。
- 本地静态读页与 Firecrawl 同 URL 各一次实测：约97字符/556ms 对约4592字符/2346ms，Firecrawl 服务返回1点。样本只说明本页抓取更完整且较慢，不足以推断总体延迟或准确率。全量Node 464项、React检查、通用检查通过；未做真实DeepSeek端到端问答，Windows构建因应用仍运行而延期。详见 `reports/2026-09-30-daisy-agent-tool-loop-firecrawl.md`。

## 结构化请求、天气路由与记忆关系检索（2026-09-30）

- 桌面 `/api/agent` 与账号 `/tasks/process` 均把原话、解析问题、sessionId/taskId、当前对象、请求字段、产品配置、价格类型、地点/日期、候选、冲突和来源依据传入同一个 `request`；Daisy 的工具规划与证据检查以该结构为准。请求理解只看用户消息，助手旧回答不升级为事实。
- 对象切换会清理旧设备专属年款/芯片/内存/存储，同时只继承有依据的查询任务字段和平台/价格类型。字段保留用户消息中的原始轮次和简短原文依据；型号候选保持未确认，直到工具证据确认。
- 当前天气会话允许单独城市词替换地点（例如“杭州”），但没有活动天气上下文时不会将孤立城市名强制联网。切换地点后明日追问继承新地点；天气工具未返回指定地点/日期成功数据时，最终答案不得给出具体天气值。
- 当前会话自述与持久记忆分开：同轮“喜欢香蕉、偶尔吃苹果、查询苹果好处”保留为两条关系事实和独立问题，不把偶尔行为升级为偏好。明确“记住……并查……”先完成显式保存，再继续问题；未保存成功不得声称已保存。保存与管理仍使用原有本机/账号身份边界。
- 本地与账号记忆检索共用 `src/agent/personal-facts.mjs` 的词项与关系评分规则；当前只对常见水果类别和喜欢/食用/频率关系提供有限的类别检索，不是通用语义理解或向量检索。没有匹配的私有记忆不会将个人偏好问题转为公开网页搜索。
- 2026-09-30固定样本：全量 Node 测试500/500；React 类型检查和Vite构建通过。真实Open-Meteo连续四步“张家港→南京→杭州→明天”四步均成功；当前DeepSeek实时产品问答实际发出2次搜索并返回回答，但只取得摘要且没有正文读取，本次不能证明回答质量提升。真实模型调用次数/用量不在该运行摘要中，标记未记录。详细记录见 `reports/2026-09-30-context-routing-memory.md`。

## 多轮纠正、公司新闻与设备定位（2026-09-30）

- `resolveQuestionContext` 记录天气改口中的原话、撤销范围/地点与替代值；同轮或跨轮“一个月→一周”只把最终区间交给工具。“不是南京，是杭州”替换地点；比较两地保留两个地点。
- 天气地点与日期独立解析。缺城市请求可等待补充，用户回答“南京的”后继承待查日期。明确城市优先于设备位置；缺少对应地点/日期成功工具结果时不输出实时数值。
- 公司新闻有独立请求字段：公司、新闻任务、Asia/Shanghai 日期窗口与所需事件/发布时间/来源。“最近”当前默认近7天；文章发布时间与抓取时间分开，过时或无发布日期材料不能证明近期新闻。
- 可选设备位置仅在用户主动授权后读取，低精度、短期内存缓存；只向天气工具提供取整近似坐标，不进入回答模型上下文、历史或记忆。拒绝/不可用可手动填城市，联网开关单独控制。
- 自动测试、真实天气/新闻结论和待验收桌面行为见 `reports/2026-09-30-multiturn-news-weather-location.md`。Windows Tauri 系统权限弹窗与撤销尚未实机验收；当前实时新闻证据仍不足。

Windows 定位能力补充：当前依赖 Tauri WebView 的 `navigator.geolocation`。已核对项目锁定的 Tauri 2.11.5 / Wry 0.55.1 源码，未发现应用层可配置的通用 WebView 权限处理器；Microsoft WebView2 有地理位置权限类型，但 TalkCraft 实际窗口返回行为尚未测试。因此UI当前只承诺“尝试系统定位并提供手动城市后备”，不宣称系统权限弹窗/位置读取已工作。需新版本桌面验收；若被拒绝，再评估原生定位命令或安全升级路径。
